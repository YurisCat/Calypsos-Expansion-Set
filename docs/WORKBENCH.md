# 雕像待办清单（本地需求工作台）

工作台把方案选择、开发进度和验收证据放在同一页面。页面每两秒读取项目文件；选择、备注和优先级自动写回本地文件，后续开发可直接读取。

会话中的“待办清单”默认指此页面；需要维护项目状态文件时明确称为 `TODO.md`。

## 打开与关闭

本地交付目录为 `人类工作间/接收文件/雕像需求对齐_20261013_v1/`，页面和需求文件不进入 Git。需有该交付目录，以及 Python 3.10 或更新版本；后台仅使用 Python 标准库。

双击桌面「雕像需求实时工作台」即可启动后台并打开浏览器。重复点击复用本项目已经运行的服务。也可在项目根运行：

```powershell
.\scripts\Open-IdolWorkbench.ps1
```

默认地址为 `http://127.0.0.1:18764/`，只监听本机。关闭标签页后后台继续运行，再次打开可继续使用。需要退出后台时，先确认页面显示已保存，再运行：

```powershell
.\scripts\Open-IdolWorkbench.ps1 -Stop
```

`-NoBrowser` 只启动后台，`-Port` 指定其他端口。项目目录移动后需要更新快捷方式中的脚本路径。工作台不会启动游戏或部署插件。

直接打开 `index.html` 会显示启动指引。旧离线页保留为 `index_离线原版20261013.html`；其中的浏览器答案可先导出 JSON，再通过新页面「导入进度」迁移。

## 雕像图鉴

工作台顶部「雕像图鉴」在新标签页打开 `/wiki/`，展示手绘便签、正式名称、箴言与简短玩法。默认使用小便签的「紧凑」模式，也可切换「大图」；支持名称/箴言/玩法搜索、分类与启用状态筛选、放大查看及单条雕像链接。当前收录十六种启用内容，含退行与游移的正式手绘；未实现的需求、历史 spring 原型不混入图鉴。

右上角可切换中文／English，名称、箴言、简述和页面操作一并切换；中英文都可用于搜索。语言和预览大小保存在本机浏览器，直达链接中的 `?lang=en` 或 `?lang=zh-CN` 优先于保存的语言；复制雕像链接会带上当前语言。浏览器存储不可用时仍可正常切换，仅不保存偏好。

中文名称、箴言、图案 key 和启用状态读取当前定义；英文名称和箴言按配置 ID 与 key 从 `UI/IdolTextLocalization.cs` 读取，沿用游戏内确认文案。中文简述优先使用需求条目的 `wikiSummary`，缺省沿用 `summary`；英文简述在 `scripts/workbench/wiki.en.json` 中维护。玩法说明修改时同步维护两种语言，不能假设英文会自动翻译。页面每五秒刷新，表示当前项目内容，不表示已安装版本或游戏验收结果。图鉴为只读页，不修改选择、备注或优先级。

页面源码位于 `scripts/workbench/`，同一后台提供 `/api/wiki` 与白名单图片路由。图片来自 `Assets/StickyNote/Previews/`，仅展示绘画参考蓝框内部并使用纯黄色纸底；范围、更新方式及显示边界见 [便签说明](../Assets/StickyNote/README.md#正式手绘与图鉴裁图)。更改后台路由后需重启服务；更新页面、源码文案或图片不需重启。

## 数据与实时更新

| 来源 | 用途 |
| --- | --- |
| `需求数据.json` | 需求、问题、行为说明、验证证据与未完成验收 |
| `需求进度.json` | 选择、备注、需求确认与优先关注；网页和开发均可读取 |
| `CalypsoExpansionSetPlugin.cs`、`Idols/*.cs` | 实时识别插件版本、当前注册类型、稳定身份与 ContentVersion |
| `TODO.md`、`docs/ARCHITECTURE.md`、`CHANGELOG.md`、`DEVELOPMENT.md` | 页面底部的当前待办、设计与证据原文摘录 |

源码启用、需求确认、编译、托管模拟、单人游戏和多人验收分别记录。源码的 ContentVersion 与行为说明基准不同，卡片会提示「行为说明待更新」。文字说明由开发维护，不会根据任意源码变更自动推断玩法或宣布验收通过。

网页更改约 0.45 秒后自动保存。每次写回前保存原进度到交付目录的 `进度备份/`，随后以临时文件原子替换正式文件。断线时保留浏览器草稿并自动重试；确认保存前不要清除浏览器数据。

多个页面或开发同时修改时会检查文件版本。发生冲突后停止覆盖，页面提供「导出本页草稿」和「载入最新文件进度」；先保存需要保留的草稿，再按需合并。导入整个进度文件会替换本页选择和备注，操作前有确认，原文件自动备份。

## 开发维护

处理具体需求前，读取本地 `需求数据.json` 与 `需求进度.json` 中对应条目的选择、备注和优先级。实现或验收发生变化后，同步更新对应条目的 `summary`、`implementation`、`evidence`、`acceptance` 与版本基准；源码注册和项目文档由后台持续读取。

保留稳定 `id` 和 `key`，问题答案按标签保存；重命名问题时保留历史答案，不能默默改写用户选择。更新 JSON 时先校验，再用同目录临时文件原子替换。不要用旧版静态页面生成脚本覆盖实时交付目录。

工作台提供实时文件同步；开发工作仍由明确的任务启动。页面不会自动发起模型任务，也不会仅因勾选需求确认就修改游戏。
